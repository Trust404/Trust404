# User Flow

## 1. 목적

Trust404 사용자가 중고거래 정보를 입력한 뒤
AI 위험 분석 결과를 확인하기까지의 전체 흐름을 정의한다.

Trust404 MVP는 별도의 회원가입이나 로그인 없이
거래 전 위험 분석 기능에 바로 접근할 수 있도록 구성한다.

---

## 2. 기본 사용자 Flow

홈
↓
거래 정보 입력
↓
입력값 검증
↓
분석 요청
↓
분석 중
↓
분석 결과 확인

### 상세 흐름

1. 사용자가 Trust404에 접속한다.
2. 거래 분석 화면으로 이동한다.
3. 판매글 내용을 입력한다.
4. 판매자와의 채팅 내용을 입력한다.
5. 전화번호 및 계좌번호 등 거래 정보를 입력한다.
6. 사용자가 `거래 위험 분석` 버튼을 누른다.
7. 입력값이 올바른지 검증한다.
8. Backend 분석 API에 거래 정보를 전달한다.
9. Trust404가 다음 항목을 분석한다.
   - 사기 의심 위험 신호
   - 판매글과 채팅 사이의 거래 조건 모순
   - 안전거래 정책과의 충돌
   - 신고 이력 정보
10. 분석 결과를 종합하여 위험도를 계산한다.
11. 사용자에게 분석 결과를 보여준다.

---

## 3. 입력 화면

사용자가 분석을 위해 거래 정보를 입력하는 화면이다.

### 입력 항목

- 판매글 텍스트
- 채팅 내용
- 전화번호
- 계좌번호
- 기타 필요한 거래 정보

### 주요 동작

- 거래 정보 입력
- 입력값 Validation
- `거래 위험 분석` 버튼 클릭

---

## 4. 분석 중 화면

분석 요청 후 결과가 반환되기 전까지
사용자에게 현재 분석 중임을 안내한다.

### 표시 내용

- 분석 중 메시지 또는 Loading UI
- 중복 분석 요청 방지
- 분석 버튼 비활성화

---

## 5. 결과 화면

분석이 완료되면 다음 정보를 사용자에게 제공한다.

### 종합 위험도

- LOW
- MEDIUM
- HIGH

### 결과 정보

- 종합 위험 점수
- 신고 이력 결과
- 탐지된 위험 신호
- 위험 신호별 판단 근거
- 판매글과 채팅의 거래 조건 모순
- 안전거래 정책 충돌 또는 주의사항
- 거래 전 권장 행동

---

## 6. 예외 Flow

### 입력값이 부족한 경우

거래 분석에 필요한 필수 정보가 누락된 경우
분석 API를 호출하지 않고 사용자에게 입력 오류를 안내한다.

입력
↓
Validation 실패
↓
오류 메시지 표시
↓
사용자가 입력 수정

### 분석 API 호출에 실패한 경우

분석 과정에서 서버 또는 네트워크 오류가 발생하면
사용자에게 분석에 실패했다는 메시지와 재시도 방법을 제공한다.

분석 요청
↓
API 오류
↓
오류 화면
↓
재시도

### AI 분석에 실패한 경우

LLM Timeout 또는 분석 결과 처리에 실패한 경우
서비스가 종료되지 않도록 오류를 처리하고 재시도를 안내한다.

### 신고 이력이 없는 경우

신고 이력이 없다는 것은 안전하다는 의미가 아니므로
정상적인 분석 결과로 처리한다.

신고 이력 0건
↓
AI 위험 신호 분석 계속 진행
↓
종합 위험도 산출
